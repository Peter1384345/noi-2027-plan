## 今日主线

两条线的提问方式同时发生变化。coding 侧不再问"模型能写多少代码"，而是问"跑一轮 agent 的边际成本是多少、延迟卡在哪一段"——Anthropic 用一份招股书修订稿把单位经济学摊开，用一次 API 改动把瓶颈从算力挪到工程链路。具身侧不再问"能不能爬上"，而是问"在 3100 级高低不一的台阶上、在酒店布草间和超市货架前，能连续站多久"——泰山与马鞍山分别从竞技与制度化两个方向给出了同一种考法。

## 1. Anthropic 修订招股书：8954 亿美元算力承诺，单位经济学首次转差

**事件**　11 月 2 日（美东）Anthropic 向 SEC 提交 S-1 修订稿，补齐 2026 财年第三季度（截至 9 月 30 日）数据：

- 营收 **169.56 亿美元**，同比 **+1127%**，环比 +46.7%（Q2 环比增幅为 144%，增速明显放缓）；前三季度累计 332.42 亿美元。
- 总运营费用 175.23 亿美元（同比 +292%），其中**算力与基础设施支出 98.63 亿美元**（同比 +382%），相当于当季营收的 **58%**（Q2 约 48%）。
- **经营亏损 5.67 亿美元**，而 Q2 刚实现首次经营盈利 9.74 亿美元。净亏损 232.91 亿美元（同比扩大 92%，主要由可转换票据、衍生负债、SAFE 公允价值变动等非现金项目构成）。
- 算力采购与租赁**承诺总额约 8954 亿美元**：约 4475 亿在 2030 年底前兑现，约 698 亿在 12 个月内到期，其余主要落在 2031—2045 年。9 月底流动性约 1466 亿美元（现金 956 亿 + 短期投资 363 亿 + 可用授信 148 亿）。

两个直接诱因：需求超预期导致**临时加购 50 亿美元短期算力**（价格明显高于 12—18 个月长约），以及新模型降价与合同折扣使当季收入减少约 6 亿美元。

**值得关注的原因**

1. **一个可比价的效率指标出现了**：每 1 美元算力与基础设施投入带来的收入，从 Q2 的 **2.08 降至 1.72**，为首次下滑。这是"agent 规模化到底会不会自然收敛到盈利"的第一个公开反例——目前不收敛，只能靠长约与自建算力（Anthropic Direct、直接租芯片、专用数据中心）把成本压回去。
2. **对采购方是定价信号**：Claude Code 是这轮 coding agent 的定价基准。成本端承压 + 促销端让利 6 亿美元，说明当前的额度与单价包含补贴成分。企业做 2027 年预算时，应按"单价回升 + 额度收紧"做情景，而不是按今年的斜率外推。
3. **需求端的增长是真的**：付费超 10 万美元的企业客户超 1.19 万家，超 100 万美元约 1900 家，超 1000 万美元约 250 家。这组数字比营收更能说明 coding agent 已进入企业常规预算科目。

## 2. Anthropic 开放 message threads 公测：长跑 agent 的瓶颈从算力移到工程链路

**事件**　Messages API 新增 thread 机制：首个请求携带完整会话并开启 thread，此后每轮仅发送**新增消息 + 上一次响应的 ID**。thread 在两次请求之间保存在内存并加密、**不落盘**，最后一次请求后 **5 分钟过期**，过期后客户端需重发完整对话开启新 thread。官方数据：对 50 万至 100 万 token 的请求，**首 token 延迟（TTFT）中位数下降约 35%**。该能力对多数 Claude Code 用户已默认开启。

**值得关注的原因**

1. **官方明确 token 用量没有减少**——Claude 每轮仍要读完整对话，省下的是传输与预填充时间。这个澄清很重要：上下文长度的瓶颈已经从"模型能不能读 1M"变成"每轮要不要重传 1M"，是工程问题而非算力问题。
2. **受益顺序清晰**：computer use（每一步都带截图）、图片与文档密集型工作流、长跑编码 agent。反过来说，纯文本短会话的收益接近于零，不要指望它改善成本。
3. **5 分钟 TTL 是新的设计约束**：任何超过 5 分钟的思考、等待人工审批或外部事件等待，都会退回全量传输。自建 agent 的团队需要按这个窗口重切任务粒度，否则优化在最需要的地方失效。

## 3. Vercel agent-desktop 发 v1.0 并登上 GitHub 日榜：computer use 的观察原语从像素换成无障碍树

**事件**　`vercel-labs/agent-desktop`（Apache-2.0，Rust CLI + C ABI，三端 macOS/Windows/Linux）在 10 月 27 日补齐 Linux 支持、合版发布 **v1.0.0**；截至今日约 **9,497 星，24 小时 +2,902**，位列 GitHub 日榜第 4。

核心机制：读取操作系统的 **accessibility tree（无障碍树）**，`snapshot` 返回结构化 JSON 并为每个可操作元素分配带快照 ID 的引用（如 `@s8f3k2p9:e8`），agent 对引用执行动作后再快照校验。默认 headless 模式走系统无障碍 API，**不移动鼠标、不抢前台焦点**；截图是可选命令，循环逻辑留在调用方 agent 内。

值得直接借鉴的工程细节：

- 错误语义分级：`STALE_REF`（界面已变，需重拍）、`AMBIGUOUS_TARGET`（目标歧义，需缩小范围）、`INVALID_ARGS`（引用缺快照身份）。
- 结果状态区分**"命令是否报错"与"动作是否送达"**：`not_delivered` 才允许安全重试，`delivery_uncertain` / `delivered_unverified` 必须回到界面取证据。
- 60 个命令名中 56 个可执行；`key-down/up`、`mouse-down/up` 因缺少守护进程负责兜底松开而**直接拒绝运行**——做不稳的先锁上。

**反差数据**：星标近万，但 npm 月下载量仅约 2,941 次，仓库挂着 113 个未关闭 issue/PR。看热闹的人远多于装上去的人。

**值得关注的原因**

这是"结构化观察替代视觉猜测"这条路线第一次有大厂给出可用实现与错误协议。它对 coding agent 的意义在于：验证闭环可以从浏览器与终端扩展到任意桌面应用，且不必为每一步付截图与视觉推理成本。但边界要说清——树的信息量取决于应用暴露程度（Chromium/Electron 应用稳定前树很薄，自定义画布基本无解），平台死角明确（Windows 最小化即全部 offscreen、UAC/锁屏/Session 0 不支持、Ubuntu 22.04 会崩、Wayland 拒收鼠标输入），隐私面需自担（快照、剪贴板、截图可能含敏感内容）。准确率与耗时的收益目前**没有同任务同模型的公开对照实验**。

## 4. 首届世界机器人登泰山大赛：27 分 26 秒的冠军，与担架抬离赛场的选手

**事件**　11 月 2 日于山东泰安举行，近 90 支队伍参赛，为全球首个山岳实景具身智能机器人赛事。

| 赛项 | 赛段 | 冠军 | 成绩 |
|---|---|---|---|
| 人形机器人竞速 | 约 1.6 km / 600+ 级台阶 | 智身凌岳队 | **27:26**（另以 55:34 获挑战赛段"勇闯巅峰奖"） |
| 足式机器人竞速 | 红门—中天门 约 3.9 km / 3100+ 级 | 北京灵翌科技队 | 43:41 |
| 足式机器人负重（模拟挑山工） | 约 3.3 km / 2100+ 级 | 灵锶智能灵狮队 | 1:51:29 |

赛道特征：石板路、石阶、陡坡交替，台阶高低宽窄不一，其中 2.6 km 路段垂直高差约 400 米。

**不体面但更有信息量的部分**：大量机器人在前几十级台阶即出现重心偏移；有的机器狗在终点前"累晕"；有人形机器人瘫倒在商铺门口，最终由消防员用担架抬离赛场；冠军队伍自述机器人途中因**电机过热重启两次**，脚链在赛前测试中多次损坏。

**值得关注的原因**

1. **标准赛道一直是隐含前提**。此前足式机器人的测试环境多为平整塑胶地面 + 等高标准台阶，泰山把这几个变量变成显式的：阶高差、落脚面宽度、负重位移、连续 3100 次的平衡解算。同一套模型在两种环境下的表现差距，比任何单一的峰值速度数字都更能说明泛化程度。
2. **真实短板不是速度，而是热管理与落脚决策的鲁棒性**。这两项在演示视频里看不见，在长赛道上藏不住，且直接决定工业场景的连续作业时长（回到智元的 Worken、广东"稳定在岗"口径，是同一件事）。
3. **评估口径的启示**：野外工况应要求"连续通过率 + 异常恢复记录"，而非最好成绩。冠军时间说明"能爬完"，担架离场说明"爬得还不稳"，两者并置才是当前真实段位。

## 5. 马鞍山实景实训挑战赛：考场搬进工厂、酒店与商超，11 月 16 日开测

**事件**　11 月 2 日在北京召开新闻发布会。由马鞍山市人民政府、中国电子学会、世界机器人合作组织共同主办，对应**工业和信息化部与国务院国资委联合开展的 2026 年度人形机器人与具身智能实景实训专项行动**。

- 场景与赛项：围绕"具身智能 + 物流 / 制造 / 服务 / 安全 / 文体"5 大场景设 **13 个赛项**。物流分拣与快递配送；物料搬运上下料、精密装配（毫米级插装、柔性力觉控制）、拔河与载重；酒店清洁、酒店叠物、超市补货；应急救援（断桥通行、废墟突围、管廊巡检、涉水排险）；乒乓球、羽毛球、综合格斗、诗词创作。
- 赛制：**测试赛 11 月 16 日—12 月 3 日**，直接进入马鞍山本地工业制造企业、物流企业、酒店、超市与社区，在真实工作环境开展；**挑战赛 12 月 4—6 日**在市体育会展中心，同期举办人工智能赋能新型工业化"深度行"（马鞍山站）与**工信部人形机器人与具身智能标委会企业座谈会**。报名截至 11 月 27 日。

**值得关注的原因**

1. **评测正在从"指标"换成"岗位"**。与 10 月底发布的首批六项人形机器人国标、以及 11 月 1 日实施的数据集质量标准相比，这次把机器直接放进酒店的布草间、超市的货架通道、工厂的上下料工位——考的是同一台设备在真实节拍与真实干扰下连续数周的表现。这比任何单项指标更接近采购决策的实际问题。
2. **会产出两类稀缺物**：一是带失败样本的可比真机数据（当前行业最缺的不是成功视频，是失败归因），二是"哪类赛项企业愿意付费复购"的早期信号。
3. **需要区分口径**：测试赛是赛事方组织的实景测试，不等同于商业交付；"考场搬进企业"也不等于企业买单。真正有价值的观察点，是 12 月之后这些赛项背后有多少转为订单。
