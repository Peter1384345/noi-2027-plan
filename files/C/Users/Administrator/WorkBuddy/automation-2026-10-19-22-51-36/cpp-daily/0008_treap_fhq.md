## 一、为什么高效

Treap 用一个思路替代了红黑树的全部旋转规则：**把平衡交给随机数**。

| 维度 | `std::set`（红黑树） | Treap（本期的 FHQ 版） |
|---|---|---|
| 平衡依据 | 颜色不变式 + 插入修复（3 种情形 × 对称） | 随机优先级 + 堆序，无修复逻辑 |
| 实现代码量 | 库内 ~800 行（含迭代器/分配器） | 核心 40 行（split + merge） |
| 预期树高 | ≤ 2·log₂(n+1)，n=1e5 约 33 | ≈ 4.31·ln n，n=1e5 实测 38，n=1e6 约 60 |
| 每层代价 | 指针 + 颜色位，比较一次 | 指针 + 32 位优先级，比较一次 |
| 排名 / 第 k 小 | **不支持**（需 PBDS 扩展） | 原生支持，O(log n) |
| 区间翻转 | 不支持 | O(log n)（lazy 标记） |
| 可持久化 | 不支持 | O(log n) 新节点/次 |
| 每节点空间 | 3 指针 + 颜色 ≈ 32B | l, r, key, pri, sz = 20B（数组池，无分配器头） |

结论：Treap 的单点操作常数与红黑树同量级（甚至略优，因为无需颜色维护与旋转分支），
但**能力面大得多**——凡是"把树切开再拼回去"能表达的操作，它都能做。这就是它在竞赛与
工程（如 `std::map` 替代、区间维护、可持久化结构）中长期占位的原因。

附加收益：**分裂/合并是组合原语**。区间翻转、区间加、集合合并（启发式合并）、可持久化、
按位置插入删除，全部由同一组 `split` / `merge` 派生出，不需要各自写一套平衡逻辑。

## 二、原理

### A. Treap 的定义与唯一性

每个节点带一个随机优先级 `pri`，同时满足：

- **BST 性质**：左子树 key < 根 key < 右子树 key；
- **大根堆性质**：根的 `pri` ≥ 两个孩子的 `pri`。

给定键集合与优先级赋值，满足两性质的树**唯一**（同 Cartesian 树与序列的一一对应）。
因此"插入一个节点"不是"找一个位置塞进去"，而是"构造满足约束的唯一树形"——
这正是 `split` + `merge` 的语义。

期望深度：随机优先级等价于随机 BST，平均深度 ≈ 4.311·ln n，最坏 O(n)（概率 ~ 1/n!）。

### B. 两个原语

```
split(x, key) -> (a, b)   // 把树 x 按 key 切成两棵，各自仍是合法 Treap
merge(a, b)   -> x        // 前提 max(a) < min(b)，按优先级选根递归
```

`split` 的实现只有两句真话（以 `split_lt` 为例，`a` 收 < key，`b` 收 ≥ key）：

```cpp
if (t[x].key < key) { a = x; split_lt(t[x].r, key, t[x].r, b); }  // x 归左，切右子树
else                { b = x; split_lt(t[x].l, key, a, t[x].l); }  // x 归右，切左子树
pull(x);
```

`t[x].r` 同时作为入参和出参看似危险，实际上是安全的：形参 `x` 按值先拷贝，
递归内部改写的是成员 `t[x].r`，两者不冲突。**这是 FHQ 最不像教科书、却最省代码的写法。**

### C. 为什么需要两种分裂语义（`split_lt` 与 `split_le`）

一次"存在则更新、否则插入"的插入需要把 `== key` 的那一段单独摘出来：

```
split_lt(root, key) -> (a, b)      a: < key      b: >= key
split_le(b,    key) -> (c, d)      c: == key     d: > key
```

只用 `split_lt` 也可以：先 `split_lt(root, key)` 再 `split_lt(b, key + 1)`。
但 `key + 1` 在 `key == INT_MAX` 时**有符号溢出（UB）**。本期专门提供 `split_le` 绕开这个坑，
代价只是多 6 行几乎对称的代码。

### D. 集合操作如何映射到原语

| 操作 | 实现 | 复杂度 |
|---|---|---|
| `insert(k)` | split_lt + split_le + 2×merge，`c` 非空即已存在 | O(log n) |
| `erase(k)` | 同上摘出 `c`，回收后 merge(a, d) | O(log n) |
| `rank(k)` = count_lt | 一次下行：走右子树时累加 `sz(left)+1` | O(log n)，迭代 |
| `kth(k)` | 按左子树规模下行 | O(log n)，迭代 |
| `prev/next` | `kth(rank(k) ± 1)`，两次下行 | O(log n) |

注意 `insert` **不需要先 contains**：`c` 是否为空就是存在性判断，一次路径完成。
写成 `if (contains) … else …` 会让每次插入多走一遍 O(log n)，这是常见的隐性 2× 开销。

### E. 隐式键：从集合到序列

把"按 key 分裂"换成"**按排名分裂**"，键值就退化为无意义的载荷：

```cpp
void split_sz(int x, int k, int& a, int& b) {   // a: 前 k 个元素
    push(x);                                     // 必须先落实 rev！
    int ls = t[t[x].l].sz;
    if (k <= ls) { b = x; split_sz(t[x].l, k, a, t[x].l); }
    else         { a = x; split_sz(t[x].r, k - ls - 1, t[x].r, b); }
    pull(x);
}
```

此时树的中序遍历就是序列本身，于是支持：任意位置插入/删除、区间翻转、区间和、
区间加（再加一个 add 标记）、区间第 k 小（配合可持久化）。**这就是"文艺平衡树"。**

### F. 区间翻转的 lazy 标记

翻转一段序列 = 交换区间内每个节点的左右子树。逐个交换是 O(len)；
在区间子树的根上打一个 `rev` 标记，把交换动作推迟到"真正要访问它的孩子"时：

```cpp
void push(int x) {
    if (!x || !t[x].rev) return;
    swap(t[x].l, t[x].r);
    if (t[x].l) t[t[x].l].rev ^= 1;
    if (t[x].r) t[t[x].r].rev ^= 1;
    t[x].rev = false;
}
```

关键性质：**`sum` 与 `sz` 对翻转不敏感**（元素集合不变），所以 `pull` 里完全不用考虑 `rev`；
只有"顺序"相关的量（第 k 个是谁、中序输出、区间边界）才需要先 `push`。

三处必须 `push`：`split_sz` 入口、`merge` 选中根之后、`at` / 中序遍历下行时。

### G. 可持久化：路径复制

`split` / `merge` 只沿一条根到叶的路径递归，路径上的节点被"复制一份、改指针"，
路径外的子树**整棵共享**：

```cpp
void split_lt(int x, int key, int& a, int& b) {
    if (!x) { a = b = 0; return; }
    if (t[x].key < key) {
        int na, nb; split_lt(t[x].r, key, na, nb);
        a = mk(t[x].l, na, t[x].key, t[x].pri, t[t[x].l].sz + t[na].sz + 1);  // 复制
        b = nb;                                                               // 共享
    } else { /* 对称 */ }
}
```

每次操作新增 O(log n) 个节点，已发布的版本根**永不修改**——旧版本可以一直查询。
本期 G4 用 400 次插入构造 268 个版本、5244 个节点（平均 19.6 节点/版本，与 log₂ 量级吻合），
逐版本核对第 k 小与越界哨兵全部一致。

## 三、复杂度对比

| 操作 | FHQSet | RotTreap | `std::set` | 说明 |
|---|---|---|---|---|
| insert | 期望 O(log n) | 期望 O(log n) | O(log n) | FHQ 常数略低（无旋转分支） |
| erase | 期望 O(log n) | 期望 O(log n) | O(log n)（摊还） | FHQ 走两遍路径（split + merge） |
| rank / kth | O(log n) | O(log n) | **不支持** | 唯一硬差距 |
| 前驱/后继 | O(log n) | O(log n) | O(log n)（迭代器） | |
| 区间翻转 | — | — | — | FHQSeq O(log n)；vector O(len) |
| 按位置插删 | — | — | — | FHQSeq O(log n)；vector O(n) |
| 可持久化 | — | — | — | 每次 O(log n) 新节点 |
| 最坏单次 | O(n) | O(n) | O(log n) | Treap 最坏依赖随机性 |
| 空间/节点 | 20B | 20B | ~32B + 分配器头 | 数组池 vs 独立分配 |

实测参考（x86-64，`-O2`，N=4e5，量级）：建树 fhq ≈ 0.10–0.15s / rot ≈ 0.12–0.18s /
`std::set` ≈ 0.10–0.15s；rank+kth 混合 4e5 次 ≈ 0.05–0.08s。**以本机实跑输出为准。**

## 四、代码要点

1. **NIL 用 0 号节点**，`sz = 0`，于是 `pull` 里的 `t[t[x].l].sz` 无需判空，`merge` 直接 `return a | b`
   （两个下标位于空树时必为 0，按位或即可）。
2. **`pull` 的位置**：`split` 递归返回后对自己 `pull`；`merge` 两个分支各自 `pull` 后再返回。
   漏一处 `sz` 就会在后续 `kth` 上表现为随机错位，很难定位。
3. **优先级取 32 位随机数的高位**（`xr64() >> 11`），不要用 `rand() % 32767`——后者大量并列，
   树高显著劣化。
4. **集合三件套**：`split_lt` + `split_le` + 两次 `merge`，一次路径完成插入/删除/存在性判断。
5. **`kth` 用迭代**而非递归：常数更小、无栈风险，且天然支持越界返回哨兵。
6. **`FHQSeq` 的 `push` 必须在读 `sz` 之前**：`push` 会交换左右孩子，之后 `ls` 才是翻转后的真实值。
7. **持久化不要持有 `Node&` 跨 `mk()`**：`mk` 内部 `push_back` 可能重分配，引用会悬空；
   全部用下标访问（`t[a].l` 每次重新取）。
8. **回收策略**：`FHQSet` 用显式栈回收整棵子树（避免深递归），`FHQSeq` 的 `erase_at` 故意不回收
   （回收一棵带 lazy 标记的树要先 `pushdown`，为教学简洁性让位，见练习 3）。

## 五、常见坑（含本期实测）

1. **接口不对齐 → 编译期才炸**：对拍框架对集合实现统一调用 `insert/erase/contains/count_lt/kth/
   prev_lt/next_gt`，而 `RotTreap` 初版只实现了前四项。Python 镜像跑到 G2 立刻报
   `AttributeError: 'PyRotTreap' object has no attribute 'prev_lt'`——C++ 侧对应的是模板实例化失败，
   在无编译器的环境下**肉眼不可见**。教训：多实现对拍必须先固定一份接口清单（traits/概念）。
2. **`key + 1` 上界分裂溢出**：`INT_MAX + 1` 是有符号溢出（UB）。必须用 `split_le`。
3. **`kth` 越界哨兵与真实键冲突**：本实现用 `INT_MIN` 当哨兵，若集合里真有 `INT_MIN`，
   调用方无法区分。工程上应改为 `bool kth(int k, int& out)`。G5 显式验证了哨兵行为，
   **不代表这种设计可以进生产**。
4. **忘记 `push` 就分裂**：`rev` 未落实时 `sz` 的左右分布是镜像的，`split_sz` 会切错位置，
   序列被静默打乱（对拍表现为 `first diff @i`，而不是崩溃）。这是 lazy 标记最典型的故障形态。
5. **优先级并列**：`pri` 相同时 `merge` 走固定分支，仍满足 BST，但会轻微劣化树高；
   32 位随机下 1e6 节点出现碰撞是必然的（生日悖论），影响可忽略；用 16 位随机则会明显退化。
6. **递归深度**：期望 ~4.31·ln n，1e6 节点约 60 层，安全。但若把种子固定成递增序列
   （例如 `pri = cnt++`），树退化成链，5e5 节点即栈溢出。
7. **删除不回收 = 内存单调增长**：反复"插入-删除"的负载下，池只增不减，与 0007 哈希表的
   教训一致。本期 `FHQSet` 用空闲链表解决，G1 结束后 `pool=153 / free=19` 可验证复用生效。
8. **可持久化 + lazy 不能混用**：`rev` 标记写在节点上，而节点被多个版本共享 → 一个版本的翻转
   会污染其它版本。可持久化区间结构需要"翻转时新建节点"或改用不共享的持久化线段树。

## 六、配套练习

1. **基础**：给 `FHQSet` 加 `merge_sets(a, b)`（两个有序 Treap 合并，O(m·log(n/m))），
   用于"启发式合并"：每次把小集合并进大集合，总复杂度 O(n log² n)。
2. **基础**：把 `FHQSet` 改成 multiset（节点加 `cnt` 字段），支持 `count(x)` 与 `erase_one(x)`；
   注意 `split_le` 摘出的 `c` 可能是一棵含多节点的树。
3. **进阶**：`FHQSeq` 加区间加 + 区间最小值（双 lazy：`add` 与 `rev`），
   写出 `pushdown` 的正确顺序并说明为什么 `rev` 必须在 `add` 之前或之后（给出反例）。
4. **进阶**：实现"区间按值分裂"的混合结构——支持 `split_by_key` 与 `split_by_size` 共存，
   用于"序列中插入有序块"类问题。
5. **挑战**：洛谷 P3391【模板】文艺平衡树：1..n 排列，m 次区间翻转，输出最终序列。
   用本期 `FHQSeq` 直接改主函数即可，注意 m 次翻转后必须一次中序输出（不要每次 `to_vector`）。
6. **挑战**：可持久化 + 区间第 k 小——把本期的持久化 Treap 换成**可持久化权值线段树**（0012 预告），
   并按版本做差：`root[r] - root[l-1]` 上二分。
7. **思考题**：`split_le` 在 `key == INT_MAX` 时行为是否仍正确？如果键类型改成 `unsigned`，
   `split_lt(root, 0)` 与 `split_le(root, UINT_MAX)` 分别返回什么？
