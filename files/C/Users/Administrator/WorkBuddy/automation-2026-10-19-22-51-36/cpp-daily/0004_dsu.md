# 0004 · 并查集 DSU（路径压缩、按大小合并、带权、可撤销、线段树分治）

> 一句话结论：并查集用**一个整型父指针数组**表达"谁和谁在一组"，配合**按大小合并 + 路径压缩**
> 把单次操作压到均摊 **O(α(n))**（α 是反阿克曼函数，n < 10⁶⁰⁰ 时 α(n) ≤ 4，实际等价常数）；
> 而加上"带权"可判定差分矛盾，改成"不压缩 + 记录栈"就得到**可撤销**版本，进而支撑线段树分治
> 处理**离线动态连通性**。

---

## 1. 为什么它"高效"

| 维度 | 朴素（只挂父指针） | 仅按大小合并 | 压缩 + 按大小 | 可撤销（只按大小） |
|---|---|---|---|---|
| `find` | O(n) 最坏 | O(log n) | **O(α(n)) 摊还** | O(log n) 严格 |
| `unite` | O(n) | O(log n) | **O(α(n)) 摊还** | O(log n) 严格 |
| 空间 | n | 2n | 2n | 2n + 历史栈 |
| 撤销 | ✗ | ✗ | ✗ | **O(1) 每次回退** |
| 带权（差分） | — | 可以 | **可以** | 可以 |

四条效率来源：

1. **按大小合并 ⇒ 树高 ≤ ⌊log₂ n⌋**。每次把小树的根挂到大树根下，任何节点的深度只会在
   "所在集合至少翻倍"时增加 1，因此深度被 log₂n 卡死。这是**最坏情况**的保证，不依赖输入。
2. **路径压缩 ⇒ 第二次访问几乎 O(1)**。查询时把整条链直接挂到根上，代价是一次性 O(链长)，
   但此后链上所有点都是根的直连子节点。摊还分析（势能法）给出 O(α(n))。
3. **两个优化叠加才最强**：只压缩不按大小合并，链式输入仍可能退化（单次 find 可 O(n)）；
   只按大小不压缩，深度是 log n 而非近乎常数。**二者互补**，都写才是标准写法。
4. **缓存友好**：数据结构就是一个 `vector<int>`，`find` 的内层循环是
   `while (p[x] != x) x = p[x]`——顺序内存 + 无分支预测失败，典型每次访存 1~2 个 cache line。
   相比之下，用 `struct Node { Node* parent; }` 的指针式并查集在随机访问下要多付一次指针解引用
   与潜在的 cache miss，实测通常慢 1.5~3 倍（本程序基准 1 可直接对比"压缩"有无的差距）。

## 2. 原理

### 2.1 基本形态

```
p[x] = x         →  x 是根
p[x] = y         →  x 的父节点是 y，x 与 y 同集合
find(x)          →  沿父指针走到根，返回根编号（根编号即"集合 ID"）
unite(a, b)      →  find(a) != find(b) 时，把一个根挂到另一个根下，集合数 -1
```

`find` 返回的根编号**不稳定**（合并会换根），所以**只能用于比较，不能用于持久化标识**。

### 2.2 路径压缩（两趟迭代版）

```cpp
int find(int x) {
    int r = x;
    while (p_[r] != r) r = p_[r];                 // 第一趟：找根
    while (p_[x] != r) {                          // 第二趟：整条链直接挂到根
        const int nxt = p_[x];
        p_[x] = r;
        x = nxt;
    }
    return r;
}
```

不用递归的原因：递归版在**深度大**（如未按大小合并的链）时会爆栈，而迭代版没有这个风险；
且迭代版只有两次连续内存扫描，常数更小。

### 2.3 带权（差分）并查集

维护 `d[x] = val[x] - val[parent[x]]`，根节点 `d[root] = 0`。`find` 后 `d[x] = val[x] - val[root]`。

```
find(x):
    if p[x] == x: return x
    r = find(p[x])
    d[x] += d[p[x]]        // 父已挂到根，其 d 即 val[父]-val[根]
    p[x] = r               // 顺序不能反：先用旧父的 d，再改父
    return r
```

断言 `val[b] - val[a] == w`（记 `ra = find(a)`, `rb = find(b)`）：

- **同根**：`val[b] - val[a] = (d[b] + val[r]) - (d[a] + val[r]) = d[b] - d[a]`，
  与 `w` 比较即可判矛盾。
- **异根**，把 `rb` 挂到 `ra` 下，需要 `d'[rb] = val[rb] - val[ra]`：

  ```
  w = val[b] - val[a] = (d[b] + val[rb]) - (d[a] + val[ra])
  ⇒ val[rb] - val[ra] = w - d[b] + d[a]
  ```

  若反过来把 `ra` 挂到 `rb` 下，则 `d'[ra] = -(w - d[b] + d[a])`。

理论上 `val` 可以是任意阿贝尔群（加法、模运算、奇偶性、种类取模），所以**食物链、奇偶博弈、
前缀和校验、差分约束**都是同一个模板。

### 2.4 可撤销并查集

想支持"退回历史状态"，就必须放弃路径压缩——否则撤销时要还原整条被压扁的链，代价失控。
于是只剩按大小合并，树高被限制在 O(log n)，这是**用一点查询常数换可撤销性**的经典取舍。

```cpp
bool unite(int a, int b) {
    a = find(a); b = find(b);
    if (a == b) return false;
    if (sz[a] < sz[b]) swap(a, b);
    hist.push_back({a, b, sz[b]});   // 记录：父 a、子 b、b 的旧大小
    p[b] = a; sz[a] += sz[b];
    return true;
}
void rollback(int snap) {
    while ((int)hist.size() > snap) {
        auto e = hist.back(); hist.pop_back();
        p[e.b] = e.b;            // b 原本是根
        sz[e.b] = e.szb;         // 恢复 b 的旧大小
        sz[e.a] -= e.szb;        // a 此刻仍是根，减回去即可
    }
}
```

三条不变量保证正确性：

1. **只按大小合并** ⇒ 树高 ≤ ⌊log₂ n⌋，`find` 无需压缩也是 O(log n)。
2. **不压缩** ⇒ 父指针只在 `unite` 时被改动**一次**，改动点数量线性可数。
3. **栈式回退**（LIFO）⇒ 回退时 `a` 必然还是根、`b` 的 `sz` 自成为子节点后从未被改动，
   因此 `sz[a] -= sz[b]` 与 `sz[b] = 旧值` 两条恢复操作互不干扰。

### 2.5 线段树分治：离线动态连通性

问题：m 条边，每条只在时间区间 `[l, r)` 内存在，q 次询问"时刻 t 的 u、v 是否连通"。
普通并查集只能加不能删，直接做要 O(T·m)。

做法：把"边存在的时间段"挂到**时间线段树**的 O(log T) 个节点上——

```
add(1, 0, T-1, l, r-1, u, v)       // 完全覆盖就挂在这个节点，否则递归分裂
```

然后对线段树做 DFS：

```
dfs(node):
    snap = dsu.snapshot()
    把 node 上挂的所有边 unite
    if 叶子 t: 回答时刻 t 的所有询问
    else: dfs(左); dfs(右)
    dsu.rollback(snap)              // 离开时撤销本节点新增的合并
```

**正确性**：从根到叶子 t 的路径上，所有节点挂的边并起来，恰好是"在 t 时刻存活的全部边"——
因为任意一条存活边都能唯一分解成覆盖 t 的 O(log T) 个节点。**复杂度** O((m log T + q)·α(n))，
空间 O(m log T)。

## 3. 本程序包含的五个实现

| 类 | 用途 | 关键点 |
|---|---|---|
| `DSU` | 生产用主力 | 路径压缩（两趟迭代）+ 按大小合并，维护集合数 `comp_` |
| `DSUPlain` | 对照 A | 仅按大小合并，用于量化"压缩"带来的收益 |
| `DSUNaive` | 对照 B | 只挂父指针，链式输入下退化为单链表，用于展示退化的量级 |
| `WeightedDSU` | 差分/种类 | 维护 `d[x]`，`relate` 判矛盾，`diff` 取差值 |
| `RollbackDSU` | 可撤销 | 记录 `(a, b, sz[b])`，`snapshot/rollback` O(1)/均摊 O(1) |
| `DynConn` | 线段树分治 | 时间线段树 + `RollbackDSU`，离线动态连通性 |

## 4. 代码要点

- **`unite` 内必须先 `find`**：`p[a]`、`p[b]` 只是"父"，只有 `find` 结果才是根。直接改
  `p[a]` 会挂错层级，制造出环（`find` 死循环）。
- **非根的 `sz_` 是陈旧值**：`union` 只更新根的 `sz`，所以 `size(x)` 必须 `find(x)` 后读根的 `sz`。
- **`comp_` 只在真正合并时 `--`**：`unite` 对已连通的两点返回 `false`，此时集合数不变。
- **`WeightedDSU::find` 里 `d[x] += d[p[x]]` 必须早于 `p[x] = r`**：`d[p[x]]` 是"旧父到根的差值"，
  一旦改了父指针，`d[p[x]]` 就变成"根到根"的 0，差值丢失。
- **带权值用 `long long`**：差分沿链累加，`n` 大时 `int` 会溢出（本程序 `d_` 为 `ll`）。
- **`RollbackDSU::find` 是 `const` 且不压缩**：需要能对 `const` 对象查询；不压缩是可撤销的前提。
- **`rollback` 必须按快照栈 LIFO**：任意乱序回退会破坏"`a` 仍是根"的前提，导致 `sz` 恢复错乱。
- **`DynConn::add` 用半开区间 `[l, r)`**：与 `[l, r-1]` 的闭区间写法相比，少一处 `+1/-1` 的边界错误源。
- **`DynConn` 的 `seg_` 开 4T**：线段树标准空间；T=1 时也要能正确处理（程序对拍里 T 最小为 1）。
- **对拍设计**：A/C/D 都以「BFS 重建连通分量」为金标准；B 以「真实前缀和」为金标准，
  并且只在**已连通**时才构造假关系——否则假关系会被合法接收、污染全局状态，导致后续真实关系被误拒。

## 5. 常见坑

| 坑 | 后果 | 正确做法 |
|---|---|---|
| `unite` 里不 `find`，直接 `p[a]=b` | 挂错层、产生环、`find` 死循环 | 先 `find` 取根再相连 |
| 读非根的 `sz_`/`size` | 集合大小严重偏小 | 一律 `sz[find(x)]` |
| 用 `find` 的返回值当持久 ID | 合并后 ID 变了，映射错乱 | 只用于比较；要稳定 ID 用"按时间戳编号"或另建映射 |
| 只写路径压缩、不写按大小合并 | 链式输入仍可 O(n) 单次 | 两个优化都写 |
| 只写按大小合并、不写压缩 | 深度 log n，常数偏大 | 同上 |
| 可撤销版里加入路径压缩 | 撤销无法还原被压扁的链 | 可撤销版只按大小合并 |
| `rollback` 忘 `sz[a] -= szb` | 祖先大小虚高，按大小合并失效、树高上升 | 两条恢复都写，且核对 LIFO 前提 |
| 带权 DSU 先改 `p[x]` 再加 `d[x]` | 差值算错，答案整体偏移 | 先加后改 |
| 带权 DSU 用 `int` 存 `d` | 长链累加溢出 | `long long` |
| 线段树分治 `add` 用闭区间 | 边界多算一天/漏算一天 | 统一半开区间 |
| 线段树分治漏 `rollback` | 兄弟子树被污染，答案偏"连通" | 进入 `snapshot`、退出必 `rollback` |
| 在线删边却用普通 DSU | 无法删除，答案错 | 转离线 + 线段树分治，或 LCT |
| 深链上写递归 `find` | 栈溢出（RE） | 迭代版 |

```bash
./dsu
```
