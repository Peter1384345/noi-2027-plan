## 1. 为什么需要可并堆

`std::priority_queue` 只支持 push / pop / top。一旦问题变成「**两个堆合成一个**」——
合并果子、猴王、可撤销并查集上的最值、k 路归并的动态合并——就只剩两条笨路：

- 把小堆元素逐个 push 进大堆：**O(k log n)**；
- 全部弹出再重建：更差。

可并堆把 `merge` 做成一等公民操作，左偏树给出 **O(log n)** 的单次合并保证，
且整棵树只用数组下标（`lc / rc / dist`），无指针、缓存友好。

| 操作 | 二叉堆 | 左偏树 | 斜堆 |
|---|---|---|---|
| push | O(log n) | O(log n) | 均摊 O(log n) |
| pop | O(log n) | O(log n) | 均摊 O(log n) |
| **merge** | **不支持** | **O(log n) 最坏保证** | 均摊 O(log n)，单次最坏 O(n) |
| 空间 | O(n) | O(n)（少一个 dist 字段的是斜堆） | O(n) |
| 实现 | 极简 | 简单 | 最简（不存 dist） |

选型：需要**最坏情况保证**或与可持久化/可回滚配合 → 左偏树；
只求代码短、均摊够用 → 斜堆；不需要 merge → 老实用 `priority_queue`。

## 2. 左偏树原理

每个节点存 `dist`（也叫 s-value）：**到最近一个空儿子的距离**，空节点 dist = -1。

两条不变式：

1. **堆序**：父亲键 ≥ 儿子键（本文实现为大根堆）；
2. **左偏**：`dist[lc] >= dist[rc]`，且 `dist[x] = dist[rc] + 1`。

左偏性质保证**右脊柱（一路 rc 走到底）长度 ≤ ⌊log2(n+1)⌋**——因为从 x 出发的
右脊柱每一步 dist 严格减 1，而 dist ≤ log2(子树大小)。

`merge(a, b)` 沿右脊柱递归：

```
merge(a, b):
    空? 返回另一个
    键小者作 a 的根（大根堆: 大者作根）
    a.rc = merge(a.rc, b)      # 只往右边挂
    若 dist[lc] < dist[rc]: 交换左右   # 保持左偏
    a.dist = dist[rc] + 1
```

每次 merge 的递归路径就是两棵树的右脊柱，长度 ≤ 两个 log 之和 → O(log n)。
`push` = merge(单节点)，`pop` = merge(lc, rc)——三者全部复用同一个 merge。

**斜堆**：把「dist 比较 + 条件交换」换成「无条件交换左右」。不存任何平衡信息，
单次 merge 可达 O(n)，但用势能分析可证均摊 O(log n)。本期镜像实测两者
合并路径几乎相同（13.7 vs 14.2 @ n=180000），斜堆的代码量更小。

## 3. 可删除 / 可减键：惰性标记 + 重建

左偏树**无法像二叉堆那样 O(log n) 上浮改键**（树形不是数组下标父子关系）。
工程解法与 0006 的可删除堆同型：

- `erase(id)`：只把 id 扔进死名单，**不动树**；
- `pop`：堆顶是死元素就直接丢弃（顺带从名单移除，id 永不复用）；
- **stale > live 时重建**：迭代收集所有活元素，队列式两两 merge，
  总代价 O(live)——与二叉堆 Floyd 建堆同理，队列两两合并是最优重建序。

**减键 = erase(旧 id) + push(新键, 新 id)**。Dijkstra 的 decrease-key 就这么模拟。

## 4. Dijkstra 的两种减键姿势

| 方案 | 做法 | 复杂度 |
|---|---|---|
| 重复插入 | 松弛成功就再 push 一份，弹出的过期条目跳过 | O(m log m)，堆内至多 m 条目 |
| 懒减键 | push 带 id，改进时 erase 旧 id + push 新键 | O(m log m)，**堆内活条目 ≤ n** |

两者渐近相同，懒减键的堆更小、eras­e 有额外开销；稠密图上省内存，稀疏图差异不大。
注意：**懒减键胜出的真正场景是「堆里条目数必须受限」的场合**（如按时间分层的搜索）。

本实现是大根堆，Dijkstra 需要小根堆 → **键取负**（距离非负，无溢出）。

## 5. 本期实测（Python 镜像，未编译数值待本地复核）

- G1：3 组堆 × 6000 步随机 push/pop/merge，左偏树、斜堆与 multiset 三方一致；
- G2：n=30000 随机键右脊柱 = **12**（上界 ⌊log2(30001)⌋+1 = 15）；
  **升序插入 1e5 右脊柱 = 1**——最坏插入序列下左偏树毫无退化
  （对比：普通 BST 会变成链）；升序建堆时每次 push 都是 O(1)；
- G3：30000 步可删除堆操作与 multiset 全程一致；
- G4：15 张随机图，懒减键 Dijkstra = priority_queue 版 = Bellman-Ford；
- B1：1500 个各 120 元素的堆逐个 merge（n=180000），
  左偏树平均每并走 **13.7** 个节点、斜堆 14.2（log2 n = 17.5）——
  实际常数优于理论上界，因为右脊柱长度的期望远小于最坏界；
- B1b：n=3000 / m=12000 的懒减键 Dijkstra 与堆优化 Dijkstra 距离全一致。

## 6. 常见坑（含本期真实踩坑记录）

1. **merge 交换方向写反**（本期镜像首跑真实事故）：`if (b.key < a.key) swap(a,b)`
   会把**较小**键放上根——结果既不是大根堆也不是小根堆，且**两套实现共享同一错误时
   对拍彼此一致、只有与暴力比才暴露**。教训：对拍不能只做实现间交叉，必须有独立 oracle。
2. **大根堆跑 Dijkstra**：懒减键左偏树是大根堆，直接弹出的「最大距离」当最短路用
   全盘皆错。要么改比较器，要么键取负——取负是零成本方案。
3. **左偏树"左长右短"**：右脊柱 O(log n)，**左脊柱可以 O(n)**。
   对整树递归（check、collect、析构）会爆栈——本期全部改成显式栈迭代。
   这与 Treap/Splay 的"整树高 O(log n)"完全不同，不能套用递归直觉。
4. **升序插入不退化是"白送"的**：新键最大 → 恒为新根，旧树整体挂左边，
   每次 push O(1)。但别把这条当普适规律——它只对「插入恒为新最值」成立。
5. **镜像/移植时结构体字段下标错位**（本期镜像 G3 真实事故）：节点
   `[key, id, lc, rc, dist]` 把 id 当孩子指针用 → 树里成环 → 无限递归。
   C++ 用命名字段天然免疫；手写 SoA/AoS 下标访问时建议在注释里固化布局。
6. **erase 重复调用**：同一 id 重复 erase 会让 stale 计数虚高、提前触发重建，
   甚至 stale 超过 live 后为负。入口处 `if (!dead.insert(id).second) return;` 去重。
7. **rebuild 后必须重算 live**：重建前的 live 含死节点，重建后 live = 活元素数、
   stale = 0，三者（live/stale/树）必须同一时刻快照，否则不变式断言误报。
8. **Dijkstra 的 owner 映射**：`id = push(key, owner.size())` 必须先取长度再 append；
   顺序颠倒（F4 故障注入）在 Python 是 IndexError，在 C++ `operator[]` 是**静默脏读**。
