# 0006 · 二叉堆与优先队列（Binary Heap & Priority Queue）

> 一句话主旨：堆不是"排序结构"，而是**只维护偏序中"最值"那一端**的结构。放弃全序，换来 O(1) 取极值与 O(log n) 增删——这是 Dijkstra、Huffman、定时器、Top-K 的共同底座。

本期源码：`0006_binary_heap.cpp`（单文件、含对拍与基准、返回码可判定）

---

## 1. 为什么高效：三个"少做"的决定

| 决定 | 放弃什么 | 换来什么 |
|---|---|---|
| 只维护**堆序**（父不劣于子），不维护全序 | 无法有序遍历 | 取极值 O(1)；插入/删除 O(log n) |
| 用**数组**存完全二叉树，不存指针 | 无法 O(1) 任意插删 | 零指针开销、下标算术定位父子、缓存局部性极佳 |
| 出堆时把末元素搬到根再**下沉**，而非"旋转/重构" | 需要一次 sift-down | 每次删除只用 1 条根到叶路径 |

三条合起来的效果：一次 `push`/`pop` 只触碰 ~log₂n 个元素，且它们**都落在同一条数组路径上**。相比 `std::map`（红黑树）每次操作要维护 ~log n 个节点、每个节点一次指针追逐与可能的再平衡，堆在常数因子上通常快 2–5 倍，且内存约为 1/4（无颜色位、无三个指针）。

### 隐藏的第四点：用"挖坑"代替"交换"

朴素的 sift-down 写法：

```cpp
while (child < n) {
    if (a[i] >= a[child]) break;
    swap(a[i], a[child]);   // 3 次写
    i = child;
}
```

每层 3 次内存写（swap 的读+两次写）。"挖坑法"先把待下沉的值 `v` 取到寄存器，之后每层只做 `a[i] = a[best]` 一次写，最后一次性落位：

```cpp
T v = a[i];
for (;;) {
    int best = argmax(children);
    if (!better(v, a[best])) break;
    a[i] = a[best];  i = best;   // 1 次写
}
a[i] = v;                        // 收尾 1 次
```

写次数从 `3 log n` 降到 `log n + 2`，在 `n = 2^21` 时约省 60% 的写流量。这是 `std::push_heap`/`std::pop_heap` 与所有竞赛模板的实际做法。

## 2. 原理拆解

### A. d 叉堆的布局

`0` 索引、`D` 叉：

```
子节点:  D*i+1 ... D*i+D
父节点:  (i-1)/D
最后非叶节点: (n-2)/D
```

`D = 2` 时退化为二叉堆。把它写成模板参数 `D` 不只是炫技——见第 3 节的代价分析。

### B. Floyd 建堆为什么是 O(n)

从最后一个非叶节点逆序下沉。高度为 `h` 的节点最多 `n / D^(h+1)` 个，每个至多下沉 `h` 层，单层比较 `D` 次：

```
T(n) = Σ_{h≥0} (n / D^(h+1)) · D · h = n · Σ h / D^h = n · D/(D-1)² = O(n)
```

关键在于**大部分节点在底层，几乎不用下沉**：半数节点是叶子（0 次），四分之一只下沉 1 层。而"逐个 push"的处理顺序恰好相反——先插的是上层节点，每次都要浮到顶，总代价 `Σ log i = Θ(n log n)`。

实测差距随 n 增大而拉大：n = 2×10⁶ 时 Floyd 通常只有逐个插入的 1/2 到 1/3 时间。

### C. 堆排序

1. Floyd 建大根堆（O(n)）；
2. 反复把 `a[0]` 与 `a[end]` 交换，堆范围缩为 `[0, end)` 并下沉新根（n 次 O(log n)）。

零额外内存、最坏 O(n log n)、不退化。但**它不是通用最快的排序**：访问模式是 `0 → 1/2 → 1/4` 的跳跃，缓存与分支预测都不友好；`std::sort` 的 introsort 在分区阶段是顺序扫描，实测通常快 2–4 倍。堆排序的真正价值在"在线取最值"和"内存受限"，而非替代 `std::sort`。

### D. 可删除堆（惰性删除）

`priority_queue` 不支持删除任意元素。工程上的标准解法：

- `erase(v)` **不在堆内查找**（查找是 O(n)），只把 `v` 记入 `pending` 计数器，`--liveCount`；
- `getMax()` 前循环丢弃堆顶的待删项；
- 当待删数 `stale > live`（即堆内过半是垃圾）时，一次 O(n) 重建：`release()` 取走内部数组 → 过滤 → Floyd 重建。

**摊还分析**：重建 O(n) 由至少 n/2 次删除分摊，故每次删除摊还 O(1)（外加堆顶清理的 O(log n)）；空间上界 **≤ 2 × 有效元素 + 64**。

这个结构是"滑动窗口中位数""带过期时间的定时器""Top-K 流式统计"的通用底座。

### E. 对顶堆动态中位数

- `lo`：较小的一半，**大根堆**（堆顶是这一半的最大值，即下中位数）
- `hi`：较大的一半，**小根堆**（堆顶是这一半的最小值，即上中位数）
- 不变式：`|lo| == |hi|` 或 `|lo| == |hi| + 1`

每次插入 O(log n)；中位数 = `lo.top()`（奇数个）或 `(lo.top() + hi.top()) / 2`（偶数个）。

注意本期实现返回 **2×中位数**（整数）。这是刻意的：用浮点比较中位数会在对拍时引入 `1e-16` 级误差，导致"算法对、测试假失败"。工程代码里同理——能用整数比值就别用 double。

## 3. 复杂度对比

### 操作复杂度

| 操作 | 二叉堆 D=2 | d 叉堆 D=4 | std::map（红黑树） | 有序数组 |
|---|---|---|---|---|
| 取极值 | **O(1)** | O(1) | O(1) | O(1) |
| 插入 | O(log₂n)，~1 次写/层 | O(4·log₄n)，层数减半 | O(log n)，含旋转 | O(n) |
| 删除极值 | O(log₂n) | O(4·log₄n) | O(log n) | O(n) |
| 删除任意元素 | O(n) / 摊还 O(log n)（惰性） | 同左 | O(log n) 直接 | O(n) |
| 建堆 | **O(n)**（Floyd） | O(n) | O(n log n) | O(n log n) |
| 内存/元素 | 1 个值 | 1 个值 | 值 + 3 指针 + 颜色 | 1 个值 |

### d 叉的代价模型

- `push`：上浮 `log_D n` 层 × 每层 `1` 次比较 → `log_D n` 次比较，但每层要算 `(i-1)/D`，且**比较的是同一父节点**（1 次即可）；
- `pop`：每层需在 `D` 个子节点中选最优 → `D · log_D n` 次比较。

于是 `pop` 的最优 `D` 在 `D = e ≈ 2.718` 附近，实践中 `D = 3` 或 `4` 常胜出：比较次数略增，但**树高减半 → 缓存未命中减半**。这正是 `d-ary heap` 在 Dijkstra（pop 远多于 push）中被采用的原因。

本期基准正是测这个：`D=2` vs `D=4` 的"建堆 + 2×10⁶ 次 push/pop 交替"。理论上 `D=4` 应不慢于 `D=2`；若实测更慢，通常说明比较函数太贵（元素较大、比较是字符串或结构体），此时 `D=2` 更优。

### 与其他"取最值"结构的取舍

| 需求 | 选择 |
|---|---|
| 只要最值，不要有序 | 堆（本期） |
| 要最值 + 支持任意删除 + 有序遍历 | `std::set` / 平衡树 |
| 键值范围小、整数 | 桶 / 计数 / 单调队列 |
| 要 Top-K（k 远小于 n） | 大小 k 的堆，O(n log k) |
| 要合并两个堆 | 左偏树 / 配对堆（第 13 期） |
| 要 O(1) 取最值 + O(1) 插入（懒惰） | 惰性堆 / 桶队列 |

## 4. 代码要点

1. **索引约定统一**：全篇 0-index，`child = D*i+1`，`parent = (i-1)/D`。混用 1-index 公式是 90% 的堆 bug 来源。
2. **`build` 必须 guard `n < 2`**：C++ 整数除法向零截断，`(0-2)/2 == 0`（不是 -1），`n=0/1` 时循环会访问 `h_[0]`。本期在 `build()` 开头直接 `if (n < 2) return;`。
3. **`release()` + `build()`**：可删除堆的重建要求"拿到内部数组"，`std::priority_queue` 做不到（无迭代器），这就是本期自写 `DHeap` 而非直接用 STL 的原因。
4. **`pop()` 的 `n <= 1` 分支**：`h_.clear()`；`n == 2` 时下沉范围是 1，逻辑自然正确，无需特判。
5. **比较器必须是严格弱序**：`std::less` / `std::greater`，不要手写 `<=`。
6. **`median2x()` 返回整数**：避免浮点对拍误差。
7. **基准测试的 `volatile sink`**：`-O2` 下整个基准循环可能被完全优化掉，必须把结果"泄漏"到 `volatile`。

## 5. 常见坑（含本期自查项）

| # | 坑 | 现象 / 本期处理 |
|---|---|---|
| 1 | `(n-2)/D` 在 `n<2` 时截断为 0 | 越界读 `h_[0]`；已加 `if (n < 2) return` |
| 2 | 建堆起点写成 `n-1` | 仍正确但退化为 O(n log n)，性能悄悄变差 |
| 3 | swap 版 sift-down | 正确但写流量 ×3；本期用挖坑法 |
| 4 | 惰性删除不校验值是否存在 | `pending[v]` 会"吃掉"未来合法插入的同值元素，导致丢元素。本期 `erase` 先查 `live_` |
| 5 | 重建后忘记清 `pending_` / `stale_` | 计数器漂移，堆顶永久失效 |
| 6 | 对顶堆漏掉某侧 rebalance | 中位数取到错误的一半；本期用两个 while 兜底 |
| 7 | 偶数中位数 `(a+b)/2` 溢出 | 用 `ll` 或 `a + (b-a)/2`；本期直接返回 `a+b`（ll 足够） |
| 8 | 堆排序内层边界写成 `end` 而非 `end-1` | 已排序元素被重新卷入，结果错乱 |
| 9 | 基准里 `printf` 格式串与参数不匹配 | 本项目多次踩到；本期用 `.syntax_check.py` 静态核对（结果：OK） |
| 10 | 认为 `priority_queue` 是"稳定的" | 它不保证相等元素的相对顺序，且比较器不能是 `<=` |
