## 一、为什么高效：把"历史"变成可寻址的版本

静态区间第 k 小，暴力是 `sort(a[l..r])`，每次 O(len log len)。要把它降到 O(log n)，
必须回答一个问题：**能不能用 O(log n) 的时间拼出任意区间 [l, r] 的信息？**

主席树的答案是把"信息"定义成**可减的版本差分**：

```
区间 [l, r] 的权值计数 = 版本 r 的计数 − 版本 l−1 的计数
```

版本 i 是"把 a[1..i] 逐个插入权值线段树"后的那棵树。每次插入只经过一条从根到叶的
路径（长度 ⌈log₂m⌉+1），于是**只复制这条路径**、其余子树指针直接复用 —— 这就是
**路径复制（path copying）**。n 个版本总代价 O(n log m) 而不是 O(n²)。

于是第 k 小变成：在 `版本 r − 版本 l−1` 这棵"虚拟树"上，从根往下走，
看左子树的差分计数 `cnt[left[v]] − cnt[left[u]]` 是否 ≥ k，一次 O(log m)。

**关键洞察**：可持久化不是"存储所有历史"，而是"让历史之间共享不变的子结构"。
共享比例在本期实测达到 **99.9%**（见 G5）。

## 二、原理

### 2.1 可持久化 = 路径复制（Part 0 是它最干净的形态）

`PersistArray`（可持久化数组）把这个问题剥到最裸：单点赋值 + 读历史版本。

```cpp
int setRec(int prev, int l, int r, int pos, int v) {
    if (l == r) return slot(0, 0, v);          // 新叶子
    int mid = (l + r) >> 1;
    if (pos <= mid) {
        int nl = setRec(lc[prev], l, mid, pos, v);
        return slot(nl, rc[prev], 0);          // 右子树整棵共享 prev 的
    }
    int nr = setRec(rc[prev], mid + 1, r, pos, v);
    return slot(lc[prev], nr, 0);
}
```

一次 `set` 新增 O(log n) 个节点，`roots[version]` 指向当次的新根。
**全程不修改任何旧节点** —— 这是"可持久化"与"快照"的分界线：
一旦有一行代码改动了旧节点，历史就被污染了（F5 故障注入演示的正是这件事）。

### 2.2 主席树：把"前缀"变成"版本"

| 概念 | 普通线段树 | 主席树 |
|---|---|---|
| 下标 | 数组位置 | **值域**（离散化后的 rank） |
| 节点存什么 | 区间和/最值 | 该值域区间内**元素的出现次数**（可选再存 sum） |
| 根 | 一个 | n+1 个，`roots[i]` = 前 i 个元素 |
| 区间查询 | 递归合并 | **两个版本相减**，同时向下走 |

`kth` 只有 10 行，核心是一个减法：

```cpp
int cl = cnt[lc[v]] - cnt[lc[u]];     // u = roots[l-1], v = roots[r]
if (k <= cl) { u = lc[u]; v = lc[v]; hi = mid; }   // 第 k 小在左半值域
else         { k -= cl; u = rc[u]; v = rc[v]; lo = mid + 1; }
```

注意 `u`、`v` 必须**同时**下移：任何一侧忘了跟着走，减出来的就是两棵不同子树的差。

### 2.3 countLe 与值域求和：同一套差分，换一个终止条件

- `countLe(l, r, x)`：把 x 换成秩 `need = upper_bound(vals, x)`，
  沿路径累加"被整块跳过"的左子树差分计数，最后加上叶子。
- `sumBetween(l, r, a, b)`：节点里额外存 `sum`，
  `sumLtRank(need)` 同样是"整块跳过时累加 sum 差分"，答案 = `sumLtRank(y) − sumLtRank(x)`。

这是主席树相对于小波矩阵**唯一的能力优势**：值域求和几乎零额外成本。

### 2.4 小波矩阵：位划分 + 层内 rank

把离散化后的秩按二进制位从高到低稳定划分：位为 0 的进左半区，为 1 的进右半区。

每层只存一个东西：**该层前 i 个位置中 1 的个数**（`pref`），于是
"层内区间 [L, R) 里 0 的个数" = `(R−oR) − (L−oL)`，两次减法，O(1)。

`kth` 每层做一次判断，往左半区走就让值左移一位，往右半区走就 `|1`：

```cpp
int zc = (R - oR) - (L - oL);                 // 本层区间内 0 的个数
if (k <= zc) { L = L - oL; R = R - oR; val <<= 1; }
else { k -= zc; L = zeroCnt + oL; R = zeroCnt + oR; val = (val << 1) | 1; }
```

`countLtRank` 是同一套下标变换，只是"该位为 1 时把 0 的那半区整块计入答案"。

**为什么它更快**：主席树每步是 `cnt[lc[v]]` 这种**两次随机访存 + 指针跳转**；
小波矩阵每步是 `pref[base+L]` 这种**连续数组里的两个相邻元素**。
同是 O(log σ)，常数差 2–3 倍，内存差约 5 倍（见第三节）。

### 2.5 归并树：思路最直白、代价最贵的对照

线段树每个节点存排好序的区间。`countLe` = O(log n) 个节点各一次二分 = O(log²n)；
第 k 小还要在值域上二分 ⇒ **O(log V · log² n)**。它存在的意义是提供一个
"人人都能想到"的基线，用来量化前两者的收益。

## 三、复杂度对比表

| 操作 | 暴力 | **主席树** | **小波矩阵** | 归并树 | 整体二分（离线） |
|---|---|---|---|---|---|
| 建树 | — | O(n log m) | O(n log σ) | O(n log n) | O((n+q) log V log n) |
| 区间第 k 小 | O(len log len) | **O(log m)** | **O(log σ)** | O(log V·log²n) | 一次性 O(...) |
| 区间 count ≤ x | O(len) | O(log m) | O(log σ) | O(log²n) | — |
| 区间值域求和 | O(len) | **O(log m)** | 需再加 K 层前缀和 | O(log²n) | — |
| 单点改 + 查询 | — | O(log m) 新版本 | 不支持（静态） | 需重建 | — |
| 内存 | O(len) | n(⌈log₂m⌉+1) 节点 × 20B | K(n+1) 个 int + m | O(n log n) int | O(n+q) |
| 常数（实测趋势） | — | 基准 | ≈ 少 2 倍访存 | 慢 1–2 个数量级 | 离线最省内存 |

按 n = m = 2×10⁵ 估算：

| 结构 | 内存量级 | 说明 |
|---|---|---|
| 主席树 | ≈ 3.7×10⁶ 节点 × 20B ≈ **74 MB** | 每节点 `lc, rc, cnt` + `ll sum` |
| 小波矩阵 | 18 × 2×10⁵ × 4B ≈ **14 MB** | 只有前缀计数，无指针 |
| 归并树 | n log n ≈ 3.6×10⁶ int ≈ **14 MB** | 但查询慢两个数量级 |

结论：**只要 kth / countLe，小波矩阵在空间与常数上全面占优**；
需要"按值域求和"或"带修改的版本链"时，主席树才是不可替代的。

## 四、代码要点

- **0 号节点即空节点**：`lc[0] = rc[0] = cnt[0] = 0`，递归到底不会越界，
  `kth` 里的 `cnt[lc[u]]` 对空节点也安全返回 0。省掉一堆 `if (u == 0)` 分支。
- **预分配 `reserve`**：节点数上界 `n·(⌈log₂m⌉+2)+16`。不 reserve 时
  vector 反复扩容会把 4×10⁶ 个节点搬好几遍，建树时间翻倍。
- **离散化只做一次**，`vals` 数组同时承担"rank → 原值"的反查，`kth` 最后一步 `vals[lo]`。
- **`countLe` 的两个提前返回**：`need <= 0` 直接 0、`need >= m` 直接整区间计数。
  少了这两个分支，x 落在值域外时会走进不存在的子树。
- **小波矩阵用一维大数组** `pref[lvl*(n+1) + i]` 而不是 `vector<vector<int>>`：
  每层独立分配会让层间跳转多一次指针解引用，且失去预取友好性。
- **`zeroCnt` 不是 `n/2`**：每层 0 的个数都不同，必须实算。这个偏移是小波矩阵
  唯一容易写错的地方（F4 就是这么坏掉的）。
- **`rankDepth` 独立推算节点数**：G5 用它做"账目核对"，不依赖实现自身的计数器。

## 五、常见坑

1. **版本差分的参数顺序反了**（本期真实 bug）。
   `sumLtRank(u, v, need)` 内部按 `sum[v] − sum[u]` 取差，必须传 `(roots[l−1], roots[r])`。
   我一开始写成了 `(roots[r], roots[l−1])`，结果**所有值域求和都返回负数或 0**，
   而 kth / countLe 完全正常 —— 直到镜像 G1 的求和分支才暴露。
   **教训**：一个函数内部有"方向约定"时，签名里就该体现出来（例如命名为 `sumIn(u, v)` 并加注释）。
2. **"每次插入新增 ⌈log₂m⌉+1 个节点"是错的**（本期真实认知错误）。
   权值树建在 `[0, m−1]` 上，m 不是 2 的幂时左右两段不齐，叶子深度有两种。
   实测 m=1000（位数 10）：深度分布 9..10，每次插入新增 **10 或 11** 个节点，
   总节点 10976 而不是 11000。对照组 m=1024 才严格等于 1024×11 = 11264。
   **教训**：节点数只能写"上界"，不能写"等于"；任何"等于"都要有独立推算背书。
3. **忘做路径复制**：直接改旧节点（F2）。所有版本塌成同一个节点，
   前缀 cnt/sum 依然"看起来正确"，只有真正做区间查询才会崩。
4. **小波矩阵取一侧基点用错**：往右半区跳时基点是 `zeroCnt`（0 的总数），
   偏移是 `oL/oR`（该层位置之前 1 的个数）；写成 `zL/zR` 会算出**非法下标**。
   在 Python 里是 `IndexError`，在 C++ 里是**静默的越界读**（`operator[]` 不检查）——
   同一个 bug 在 C++ 里表现为"答案偶尔离谱"，极难定位。
5. **`countLe` 的边界判据**：`need-1 <= mid` 才是"目标秩落在左子树"；
   写成 `need <= mid` 会在 `need-1 == mid` 时分错边，错 1（F3，142 处失配）。
6. **m = 1 的退化**：所有值相同，`m=1`、`K=1`、`while (lo < hi)` 一次都不进。
   若 `bits` 从 0 开始算会得到 `1<<0 = 1 < 1` 为假，`bits` 保持 1 —— 恰好正确，
   但若写成 `while ((1<<bits) <= m)` 就会死循环。G2 的全等数组专测这条。
7. **x 落在值域外**：`upper_bound` 返回 0 或 m，必须有提前返回，否则读到负下标/越界。
8. **内存估算按"节点数 = n log n"直接乘 sizeof** 会低估 1.5 倍：
   每节点除了 `lc/rc/cnt` 还有 `ll sum`，且最后一个版本不可省。
   2×10⁵ 规模下 74 MB 很可能撞上 64 MB 的老题目限制——此时换小波矩阵。

三条真实结论：

1. **5 个变异全部被抓到，但抓到的组互不相同**。G1/G2 管语义，G3 管结构，
   G4 只管 `PersistArray`，G5 只管节点账目 —— 覆盖面是"分工"出来的，不是"多测几遍"出来的。
2. **F3 只被语义组抓到**：结构不变式（cnt 前缀、sum 前缀、节点数）对"差一位"完全免疫。
   反过来 F2 是结构破坏，G3 能抓，但只给出 2 个聚合失配，而 G1 给出 663 处具体坐标 ——
   **聚合断言能判死，不能定位**，两类测试不能互相替代。
3. **F4 的失败形式是越界而非错值**：Python 立刻 `IndexError`，C++ 则是静默脏数据。
   在没有编译器、也没有 ASan 的环境里，这类 bug 只能靠"独立推算"式的断言提前拦住。

**静态检查**：`{}102/102 ()758/758 []139/139`，printf 参数配平，1 个 `main`。
