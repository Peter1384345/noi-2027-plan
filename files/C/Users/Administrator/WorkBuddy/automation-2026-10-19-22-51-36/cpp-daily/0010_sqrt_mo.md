## 一、为什么高效：根号平衡思想

线段树把问题拆成 O(log n) 层；**分块**是它的"笨而美"的对偶：把数组切成
B 个元素一块，任何区间 [l, r] 都能拆成 **O(1) 个整块 + 两侧 O(B) 个散元素**。
单次操作代价 ≈ `B + n/B`，由均值不等式，在 **B = √n** 时取最小值 O(√n)。

莫队算法则把"根号"用在**离线查询顺序**上：单次区间查询若用双指针移动，
最坏 O(n)，q 次查询 O(nq)；但只要**按特定顺序处理查询**，
双指针的总移动量可以压到 O((n+q)·√n) —— 单个查询可能很贵，
均摊到全体查询上就是根号级。这是算法竞赛中"离线换时间"的典范。

## 二、原理

### 2.1 分块三件套（`SqrtBlocks`）

| 组件 | 作用 |
|---|---|
| 块内聚合 `bsum[b]` | 整块信息 O(1) 读出 |
| 块级 lazy `blazy[b]` | 整块加法不下传，真实值 = `v[i] + blazy[i/B]` |
| 散块暴力 | 两侧不足一块的部分逐元素改，**同步维护 bsum** |

- 整块加：`blazy[b] += d`，O(1)；散块加：改 `v[i]` 与 `bsum[bl]`，O(B)。
- 区间和整块：`bsum[b] + blazy[b] * 块长` —— **块长用 `min((b+1)*B, n) - b*B`，
  残块长度 ≠ B**（这是分块第一大坑）。
- 单点赋值：`pointSet(i, nv)` = 差值转区间加，无需新代码路径。

### 2.2 莫队（`MoDistinct`）

以"静态区间 distinct 数"为例（经典 SPOJ DQUERY）：

1. **值域压缩**：distinct 只关心相等关系，`sort + unique + lower_bound`。
2. **排序**：按 `(l/B, r)` 排序，B 取 `n/√q`。均摊分析：
   - l 指针：块内每次查询最多移 B 步 → O(qB)；跨块累计 O(n)。
   - r 指针：每块内单调扫 → 每块 O(n)，共 n/B 块 → O(n²/B)。
   - 平衡 `B = n/√q` → 总移动 O(n√q + q) ≈ O((n+q)√n)。
3. **指针维护**：`cnt[]` 直方图 + 当前答案 `cur`，add/del 各 O(1)：
   值首次出现 `++cur`，值归零 `--cur`。
4. **奇偶优化**：偶数块 r 升序、奇数块 r 降序，消除跨块时 r 指针的折返。
   本期实测（n=800, q=800）：移动 28315 → 19082，**省 32.6%**。

### 2.3 带修莫队（`MoWithUpdate`）

修改会破坏"静态"假设 —— 给每个查询加一维 **t = 查询时已生效的修改数**，
按 `(l/B, r/B, t)` 三维排序，块长取 **B = n^(2/3)**：

- l 移动 O(qB)，r 移动 O(n²/B)，t 移动 O(n²q/B²·…) —— 经典结论：
  B = n^(2/3) 时三项平衡于 **O(n^(5/3))**。
- 时间指针 curT 向前 `applyUp`、向后 `revertUp`（= apply 的逆运算）：
  把 `a[pos]` 从 nv 改回 ov，窗口内则同步修正直方图。
- **值域压缩必须覆盖 初始值 ∪ 所有修改后的值**（ov 都是历史值，已含于并集）。

## 三、复杂度对比表

| 问题 | 暴力 | 分块/莫队 | 线段树类 |
|---|---|---|---|
| 区间加 + 区间和 | O(n)/次 | **O(√n)**/次 | O(log n)/次 |
| 静态区间 distinct（离线） | O(nq) | **O((n+q)√n)** | 不适用（无法合并区间 distinct） |
| 带修区间 distinct（离线） | O(nq) | **O(n^(5/3))** | 不适用 |
| 代码量/常数 | 小 | 小、缓存友好 | 中 |

分块单次 O(√n) 慢于线段树 O(log n)，但**常数小、写法直观、能做线段树做不了的
信息合并**（如不满足结合律/可减性的统计），是"能做 vs 不能做"的分界工具。

## 四、代码要点（对应源码结构）

- `SqrtBlocks`：构造 O(n) 建块；`touch` 计数器统计元素级工作量，供 G5 实证。
- `MoDistinct::solve`：模板化的排序键（parity 切换奇偶/普通），moves 输出参数。
- `MoWithUpdate::solve`：先从 rawUps 预生成时间线（每个修改记录 ov），
  再三维排序；`applyUp`/`revertUp` 完全对称。
- 每组对拍用固定 xorshift 种子（0xAAAA0001..05），C++ 与 Python 镜像序列完全一致。

## 五、常见坑

1. **残块长度**：查询整块和时块长必须按 `min((b+1)*B, n) - b*B` 算，
   最后一块常不满。
2. **bsum 双写**：散块改 `v[i]` 时必须同步 `bsum`，否则不变式破坏
   （`selfCheck()` 专门盯这条；故障注入 #1 证明它能抓住漏加 blazy/bsum 的错）。
3. **莫队扩缩顺序**：**对 distinct 计数，先缩后扩也能通过** —— 本期故障注入 #3
   颠倒顺序后测试全部通过！原因是每一步都是"窗口内合法增删"，
   cnt 不会漏计数，最终窗口状态与顺序无关。但对"过程中必须保持区间
   非空/满足约束"的题（区间最值、满足条件的计数），必须**先扩后缩**。
   —— 顺序纪律是防患于未然，不是本题的正确性来源。
4. **带修莫队的时间倒流**：`revertUp` 必须恢复 `ov`（故障注入 #2 恢复成 nv
   立刻被 G3 抓住）；修改的 pos 是否在当前窗口内要用**当下**的 curL/curR 判断。
5. **值域压缩遗漏**：带修莫队若只压缩初始数组，修改引入的新值会下标越界。
6. **块长取整**：`n/√q` 与 `n^(2/3)` 都要 `max(1, ...)`，q=1 时退化保护。

## 六、验证与实测

- **镜像对拍**（`.verify_mirror_0010.py`，与 C++ 同种子同序列）：
  - G1 分块 vs 暴力：300 规模 5000 次混合操作 + 终态逐点 + bsum 不变式，PASS。
  - G2 莫队 vs 每查询暴力：3 种值域分布（高重复/近唯一/全同值）共 800 查询，
    普通/奇偶两版答案一致且与暴力一致，PASS。
  - G3 带修莫队 vs 暴力重放时间线：250 查询 × 250 修改，PASS。
  - G4 边界专项：n=1、时间前进/倒流、全同值、l==r、n 恰为块长整数倍，PASS。
  - G5 拐点实证：n=4000, ops=2000，touch(B=4/16/63/256/1024) =
    677519 / 199361 / **167752** / 501341 / 1690565 —— U 形曲线，谷底恰在 √n≈63，
    与理论 O(B + n/B) 完全吻合。
- **故障注入 3 组**：漏加 blazy（抓到）、revert 用 nv（抓到）、扩缩顺序颠倒
  （**未抓到** → 反证出该纪律对本题是冗余保险，见坑 #3）。
- **静态检查**：`{}136/136 ()569/569 []161/161`，printf 配平，3 class、1 main。
- 基准①②③（B 扫描 / 莫队奇偶 / 带修）需编译后运行：`./0010`。
