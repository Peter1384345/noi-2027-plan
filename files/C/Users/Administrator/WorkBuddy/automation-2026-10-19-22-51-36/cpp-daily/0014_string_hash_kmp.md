# 0014 · 字符串哈希 + KMP + Z 函数

配套源码：`0014_string_hash_kmp.cpp`（C++17，`g++ -O2 -std=c++17 -Wall -Wextra` 直接编译运行）。
验证脚本：`.verify_mirror_0014.py`（Python 逐行镜像对拍）、`.fault_0014.py`（故障注入，子进程隔离）。

## 1. 三种工具的分工

字符串问题的第一层判断是：**要不要"确定性"**。

| 任务 | 暴力 | KMP | Z 函数 | 多项式哈希 |
|---|---|---|---|---|
| 找出全部出现位置 | O(n·m) | O(n+m) | O(n+m) | O(n+m) |
| 判断两个子串是否相等 | O(len) | — | — | **O(1)** |
| LCP(后缀 i, 后缀 j) 任意 i,j | O(LCP) | — | 仅 i=0 | **O(log n)**（二分） |
| 最小周期 / border | O(n²) | **O(n)** | O(n) | — |
| 是否随机化 | 否 | 否 | 否 | **是**（有碰撞概率） |

选型规则：

- 需要**逐字符确定**、可能被构造数据针对 → KMP / Z；
- 需要**大量子串比较**、答案可容忍极小误判 → 哈希（配双模）；
- 只问"模式串在不在文本里出现"、文本极大且一次性 → KMP 优于哈希（无需预处理表、无碰撞）。

## 2. 多项式哈希

把串视为 base 进制整数：

```
H(s) = Σ s[i] · base^(n-1-i)  (mod p)
H(l..r) = H(0..r) - H(0..l-1) · base^(r-l+1)
```

预处理前缀哈希与 base 的幂，任意子串哈希 **O(1)**，于是任意两个等长子串比较 O(1)。
这是哈希相对 KMP 的唯一优势：KMP 只能回答"整段模式是否出现"，哈希能回答"任意两段是否相等"。

**双模**：分别对 `1e9+7` 与 `1e9+9` 取模，两值都相等才判等。单次误判概率 ≈ 1/p₁p₂ ≈ 1e-18。
本期 G6 实测了单模为何不够（见第 6 节）。

**mod 2^64 溢出哈希**：不取模，直接让 `unsigned long long` 自然溢出。一条 `imul + add`，
比双模快 2~4 倍，误判概率 ≈ 2^-64（与双模同量级）。**代价**：基必须是奇数，且必须大于字符值域。

## 3. 基的选择：一个能被实测出来的灾难

`base = 256 = 2^8` 时，`256^8 = 2^64 ≡ 0 (mod 2^64)`，于是所有指数 ≥ 8 的项**整项消失**——
长 16 的串里前 8 个字符对哈希毫无贡献。

本期 G7 直接构造 3000 对"末 8 位相同、前 8 位随机"的串：

```
3000 对串: base=256 碰撞 3000 对 (100.0%), base=131 碰撞 0 对
```

100% 碰撞不是"概率问题"，是**代数上必然**。同一条链上：`base = 2` 只依赖末 64 个字符，
`base = 2^8` 只依赖末 8 个，`base = 2^64` 退化为只看末 1 个字符。
规则：基取 > 值域的**奇数**（131、13331、911382323），随机化基则连"卡哈希"的数据也挡得住。

## 4. KMP：前缀函数与自动机

`pi[i]` = `s[0..i]` 的**最长真 border 长度**（既是真前缀又是真后缀）。构造：

```
j = pi[i-1]
while j > 0 and s[i] != s[j]: j = pi[j-1]
if s[i] == s[j]: ++j
pi[i] = j
```

匹配时文本指针 `i` 只前进不后退，失配就走 `pi` 链；`j` 的总增量 ≤ n，总回退量 ≤ 总增量，
**均摊 O(n+m)**。注意是"均摊"：单次失配可以回退 O(m) 步。

**自动机版本**：预处理 `go[state][c]`（`O(m·σ)`），之后每字符严格 O(1)，无 while 循环。
状态 `m` 也是合法状态（`go[m][*] = go[pi[m-1]][*]`），所以**命中后不必显式复位**——
这是流式（在线）匹配的关键：字符只能看一遍时，自动机是唯一不回溯的写法。

本期 G2 用 `(状态 × 26 字符)` 共 96070 格穷举验证：`go[st][c]` 与 `pi` 回退的转移完全一致。

## 5. Z 函数与周期

`z[i] = LCP(s, s[i..])`，用最右匹配盒 `[l, r)` 复用：盒内 `z[i] = min(r-i, z[i-l])`，
盒外继续暴力扩展。每个位置被扩展的总次数 O(n)，整体 O(n)。

Z 与 KMP 的关系：`z[i]` 给出"每个后缀与原串"的 LCP，KMP 的 `pi` 给出"每个前缀的 border"，
两者可相互转化；实践中 Z 更适合"一次性求所有后缀与原串的最长公共前缀"，`pi` 更适合流式/在线。

**周期**：设 `p = n - pi[n-1]`，则 `p` 是 `s` 的**最小周期**（允许重叠）。
若还满足 `n % p == 0`，`p` 才是真正的**循环节**（`s = t^(n/p)`）。

本期 G4 用 600 组随机串把 `n - pi[n-1]` 与"暴力枚举最小 p"对拍，并对 `t^k` 与"`t^k` 砍掉末字符"
两种形态分别断言：前者 `p = |t|` 且整除，后者 `p = |t|` 但**不整除**——这正是"周期 ≠ 循环节"的分界。

**碰撞率（G6）**：15 万条长 20 的随机串，候选对数 1.12e10。

```
单模 1e9+7 : 10 对碰撞 (理论期望 11.2)
双模       : 0 对碰撞 (理论期望 0.0000)
首对冲突: "qvpekhlpkemxrxelsknv" / "qrroyhswwlzzxtisdzts"
```

单模在**十几万**规模就真的撞了，与生日界 `√(2p·ln2) ≈ 4e4` 吻合。竞赛里"单模 1e9+7 从不撞"
的经验只在小数据上成立。

**最坏文本（B1）**：`t = a^N`，`p = a^63 + b`，m = 64。

```
镜像 N=20000: 暴力 64.00 次比较/起点 (理论 = m) | KMP 39937 次 | Z 40063 次
外推 N=300000: 暴力 19,195,968 次 | KMP 599,055 次 | Z 600,945 次 => 32.0 倍
```

关键读数：**KMP/Z 的常数是 2，不是 1**（每次前进一次成功比较 + 每个位置一次失败比较），
所以最坏情况的加速比 ≈ m/2 而非 m。把 KMP 说成"比暴力快 m 倍"是错的，它快的是**阶**。

`std::string::find` 在 libstdc++ 里是 memchr + memcmp 的朴素实现，**没有周期优化**，
同一输入上仍是 O(n·m) 次字节比较，只是 memcmp 走 SIMD，常数小 10 倍左右。
结论：`find` 快是因为 SIMD，不是因为算法。

**子串 LCP 批量查询（B2）**：结论与直觉相反。

| 文本形态 | 平均 LCP | 逐字符 | 哈希二分 |
|---|---|---|---|
| 随机 26 字母 | ≈0 | 更快（常数更低） | 慢约 2 个数量级 |
| 周期 7 | 359（n=8000） | 慢 | 快 3.7 倍（Python 常数） |

逐字符是 O(LCP)，哈希是 O(log n) 但每层 2 次 64 位取模。LCP 期望很短时（随机文本，LCP≈1/σ）
逐字符根本不需要几次比较，哈希的 20 层二分纯属浪费。**只有当 LCP 可能长达 Ω(n) 时哈希才赢**。

## 7. 常见坑（含本期真实踩坑记录）

1. **基准里两侧共用 RNG 流**（本期初版真实 bug）：第一轮测暴力消耗 Q 次随机数，第二轮测哈希
   接着往下取，两侧查询序列**完全不同**，校验和必然不等。必须"先生成查询序列，再统一使用"。
   这与 0008 的教训同源：**确定性校验和的前提是确定性输入**。
2. **比较计数器的口径**（本期初版真实 bug）：Z 的第一版只在"相等"时计数，看起来比暴力少 n 倍；
   实际是没统计失败的那次比较。口径不统一时，任何"加速比"都是假的。
   统一为"字符相等性判定次数"后，KMP 与 Z 都稳定在 ≈2n。
3. **偶数基**（G7）：`base=256` 时前 8 个字符被 2^64 吃掉，100% 碰撞。基必须是大于值域的奇数。
4. **单模不够**（G6）：15 万串就有 10 对碰撞。双模或 2^64 溢出哈希，二选一。
5. **错误的 `pi` 会让匹配死循环**（F1 故障注入）：回退写成 `j = pi[j]` 会产生 `pi[i] == i` 的自指，
   `match_all` 的 `while` 变成自环。C++ 里**没有异常**，程序就是静默挂死——比错答案更难查。
   `pi` 的两条不变式必须在调试期断言：`pi[i] < i+1` 且 `pi[i] <= pi[i-1]+1`。
6. **`min_period()` 返回 0 时取模即崩**（F5）：`pi[n-1]` 直接当周期用，空 border 时返回 0，
   `n % 0` 在 C++ 是 SIGFPE、Python 是 ZeroDivisionError。周期一定是 `n - pi[n-1]`，且 ≥ 1。
7. **"结果全对"不等于"实现正确"**（F4）：把 Z 的盒内复用改成 0，z 数组**一字不差**，
   但比较次数从 4e4 涨到 1.28e6（32 倍）。只有显式的复杂度上界断言能抓。
   本期因此在 B1 里加了 `c2 <= 4n`、`c3 <= 4n` 两条断言——**正确性断言与复杂度断言必须分开写**。
8. **哈希不是决定论**：`std::unordered_map` 的哈希 + 字符串哈希叠加时，若题目要求"最小字典序"
   等确定性答案，哈希只能做筛选，最后必须逐字符验证。
9. **自动机的空间**：`O(m·σ)` 在 σ=26、m=1e6 时是 2600 万个 int（100 MB）。此时退回 `pi` 回退版，
   或只对出现的字符建表（压缩字母表）。
