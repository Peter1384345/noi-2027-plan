## 一、为什么高效：把"树上路径"折叠成"常数段区间"

序列上的区间加、区间和，线段树 O(log n) 就够。树上没有"区间"，
路径是一串分叉的节点，暴力只能逐点走 —— 深度一深就退化成 O(n)。

树链剖分解决的就是这个**表示问题**：给每个节点一个 `dfn` 序号，
使得

1. **每条重链在 dfn 上连续**（链上深度越大 dfn 越大）；
2. **每个子树在 dfn 上是一段连续区间** `[dfn[u], dfn[u]+sz[u]-1]`。

有了这两条，任何树上路径都能拆成 **O(log n) 段连续区间**，
于是"树上操作"变成"若干次线段树操作"。关键在于第 1 条为什么只需
O(log n) 段：规定每个节点向"子树最大的儿子"（重儿子）连重边，
其余为轻边。沿任意一条轻边向下，子树大小至少减半 ——
所以从任意节点到根，轻边不超过 log₂n 条，也就是重链不超过 O(log n) 条。

## 二、原理

### 2.1 两次遍历（本期全部写成迭代）

| 遍历 | 求什么 | 方式 |
|---|---|---|
| 第一次 | `par / dep / 遍历序` | BFS 式：用 `order` 数组当队列，天然给出拓扑序 |
| 逆序扫一遍 | `sz[u]`、`heavy[u]` | 子节点 sz 已就绪，取最大者为重儿子 |
| 第二次 | `top / dfn / rnk` | 栈：弹出一个链头，沿重儿子一路走到底；沿途把轻儿子压栈，各自成为新链头 |

逆序扫 `order` 求 sz 是本期的一个常数优化：不需要递归回传，
一次线性扫描就够（`for (int i = n-1; i >= 0; --i)`）。

### 2.2 路径分解（核心循环，只有 6 行）

```cpp
while (top[u] != top[v]) {
    if (dep[top[u]] < dep[top[v]]) swap(u, v);   // 让 u 所在链更深
    op(dfn[top[u]], dfn[u]);                      // 整条链一次搞定
    u = par[top[u]];                              // 跳到链头的父亲
}
if (dep[u] > dep[v]) swap(u, v);
op(dfn[u], dfn[v]);                               // 最后同链的一段
```

- 比较的是 `dep[top[u]]` 而**不是** `dep[u]` —— 决定"跳哪一侧"的依据是链头的深度，
  不是节点自身深度。写错会跳到 `-1` 或死循环（本期故障注入之外的第一号坑）。
- 每次循环至少跨过一条轻边，所以循环次数 O(log n)；每次内部一次线段树操作
  O(log n)，合计 **O(log² n)**。
- 最后一行"同链段"不能省：省掉它，`pathSum` 会少算一段，而 `pathAdd` 会悄悄少加。

### 2.3 子树操作（一行）

```cpp
seg.rangeAdd(dfn[u], dfn[u] + sz[u] - 1, d);   // 子树加
seg.rangeSum(dfn[u], dfn[u] + sz[u] - 1);      // 子树和
```

这是剖分相对"倍增/欧拉序"的真正优势：**子树天然是一段区间**，
所以"路径修改 + 子树查询"可以共存，不需要两套结构。

### 2.4 LCA 与上跳

LCA 就是路径分解循环的副产品：跳到最后同链，取浅的那个。
`ancestorAt(x, targetDep)` 更有用（换根、求"朝某方向的儿子"）：
同一条链内深度差等于 dfn 差，一次减法就能定位；跨链则整条跳上去。

### 2.5 换根（本期 G6）

以 `r` 为根时，`u` 的子树只有三种情形：

| 情形 | 判定 | 答案 |
|---|---|---|
| `u == r` | 平凡 | 全树和 |
| `u` 不是 `r` 的祖先 | `!isAncestor(u, r)` | 与原树相同：`[dfn[u], dfn[u]+sz[u]-1]` |
| `u` 是 `r` 的真祖先 | 其余 | **全树和 −（朝向 r 的那个儿子的子树）** |

情形 3 里的"那个儿子"就是 `r` 的深度为 `dep[u]+1` 的祖先，
用 `ancestorAt` 一次定位。这个"补集"技巧是换根类题目的通用套路。

## 三、复杂度对比表

| 操作 | 暴力 | 倍增 + 前缀和 | **HLD + 线段树** | LCT |
|---|---|---|---|---|
| 路径和（静态） | O(path) | **O(log n)**，常数小 | O(log² n) | O(log n) 摊还 |
| 路径加 / 路径赋值 | O(path) | 不支持（前缀和失效） | **O(log² n)** | O(log n) 摊还 |
| 子树加 / 子树和 | O(n) | 不支持 | **O(log n)** | 不直观 |
| LCA | O(path) | O(log n) | O(log n)，常数更小 | O(log n) |
| 换根子树查询 | O(n) | 需重算 | **O(log n)** | — |
| 加边 / 删边（动态树） | 不支持 | 不支持 | 不支持 | **支持** |
| 建树 | — | O(n log n) | **O(n)** | O(n) |

结论：**只读**的树用倍增前缀和更划算；一旦需要修改，HLD 是
"代码量 / 常数 / 能力"三者最平衡的选择；只有真的需要动态加删边才上 LCT。

## 四、代码要点

- **CSR 邻接表**：`estart[] + eto[]`，两次线性扫描建好。相比
  `vector<vector<int>>` 省掉 n 次小分配，遍历时访存连续 —— n=2e5 时
  建树时间差别可观。
- **全迭代建树**：`buildDfs` 用 `order` 队列 + 显式栈，深层链（n=2e5 的链）
  不会爆栈。这是本题最容易在本地"过样例、交上去 RE"的地方。
- **`SegTree`**：区间加 / 区间和 / 区间最值三合一，只在 `dfn` 下标上工作。
  查询路径必须 `push`，否则读到的是父节点尚未下推的旧值。
- **`jumpCnt`**：路径查询里累计跳链次数，专门给 G5 做复杂度实证 ——
  这一行计数器是本期的"体检指标"，见第六节 F1。
- **`subtreeContiguous()`**：O(n·depth) 的暴力自检，验证不变式(1)在
  任意次修改后依然成立（修改只动线段树，理应不影响 dfn 布局，但要证明）。

## 五、常见坑

1. **递归建树爆栈**：n=2e5 的链深度就是 2e5，递归 dfs 必挂。全迭代。
2. **`dep[top[u]]` 写成 `dep[u]`**：路径分解的比较对象错了，会跳到 `-1`。
3. **少写最后同链段**：`pathSum` 少算、`pathAdd` 少加，且只有部分用例暴露。
4. **`sz` 与区间长度混淆**：`dfn[u]+sz[u]-1` 是闭区间右端；写成 `+sz[u]`
   就多染一个点（F2 实测：G1/G2 抓得住，纯路径测试抓不住）。
5. **只读测试抓不住复杂度退化**：重儿子选错（F1）时答案全对，
   6 组里只有 G5 的跳链计数能发现 —— 复杂度必须单独断言。
6. **`ancestorAt` 的 `targetDep` 越界**：要求 `targetDep <= dep[x]`，
   否则 `rnk` 下标为负（F3 用 `+1` 偏移模拟，被 G3/G4/G6 同时抓住）。
7. **换根漏分支**：三分支里"u 是 r 的祖先"最易漏（F4 直接返回全树和，
   G4/G6 抓住）。
8. **把"折叠率"当"加速比"**：本期实测（n=32768，2000 次随机路径）——

   | 树形 | 平均段数 | 平均路径点数 | 折叠率 |
   |---|---|---|---|
   | 链 | **1.00** | 10874.8 | 10874× |
   | 菊花 | 3.00 | 3.0 | 1.0× |
   | 完全二叉树 | 13.00 | 25.0 | 1.9× |
   | 随机递归树 | 8.08 | 18.8 | 2.3× |

   完全二叉树上路径本来只有 25 个点，剖成 13 段再各花 O(log n)，
   **几何上几乎没赚**。HLD 的价值在"深树 + 需要修改"，不在"浅树 + 只读"。
   段数 O(log n) 是渐近结论，常数最多到 2log₂n，不能当成实际加速比。
