## 一、为什么高效

单调结构的本质是：**每个元素最多入队/入栈一次、出一次，因此总时间与操作次数线性相关**，而不是与"窗口大小 × 询问次数"相关。

| 问题 | 暴力 | 单调结构 | 加速比 (n=10^6, k=5000) |
|---|---|---|---|
| 滑动窗口最值 | O(n·k) | O(n) | ~5000× |
| 柱状图最大矩形 | O(n²) | O(n) | ~10^6× |
| 长度 ≤ K 最大子段和 | O(n·k) | O(n) | ~5000× |

核心不变量（以维护最大值为例）：队列内下标对应值**严格递减**。
- **队首**恒为当前窗口最大值；
- 新元素入队时，弹出所有 `≤ a[i]` 的队尾——被弹出者从此**永远不可能再成为答案**（它更小、又更早过期）。

"永远不会被需要"是单调结构正确性的唯一依据，也是它高效的原因：每个元素被 O(1) 次判定后终身淘汰。

## 二、原理与代码要点

### 1. 滑动窗口最大值（单调队列）

```cpp
for (int i = 0; i < n; ++i) {
    q.push(i);                        // 队尾弹出所有 a[j] <= a[i]
    if (i >= k) q.popBefore(i - k + 1); // 队首弹出下标 < i-k+1
    if (i >= k - 1) res.push_back(q.best());
}
```

两个动作各司其职：**队尾弹**维护单调性，**队首弹**维护窗口范围。窗口左端是 `i-k+1`，这是最容易写错的地方（见"常见坑"）。

### 2. 柱状图最大矩形（单调栈）

对每根柱子求"左右第一个更矮的位置"，以它为高的最大矩形宽度 = `right - left - 1`。一次从左到右的单调递增栈同时求出两侧边界：

```cpp
for (int i = 0; i <= n; ++i) {
    ll cur = (i == n) ? -1 : h[i];      // 末尾哨兵 -1 强制清栈
    while (!st.empty() && h[st.back()] > cur) {
        ll height = h[st.back()]; st.pop_back();
        int left = st.empty() ? -1 : st.back();
        best = max(best, height * (ll)(i - left - 1));
    }
    st.push_back(i);
}
```

弹出时结算：**栈顶的右边界是 i，左边界是弹出后新的栈顶**（第一个更矮者）。哨兵 `-1` 使最后一次弹栈覆盖剩余所有柱子，省去收尾循环。

### 3. 长度 ≤ K 的最大子段和（前缀和 + 单调队列）

`sum(l..r) = s[r] - s[l-1]`。固定右端 `i`，要最大化子段和等价于在 `j ∈ [i-k, i-1]` 内最小化 `s[j]`——正是滑动窗口最小值：

```cpp
MinQueueRing mq(s);
for (int i = 1; i <= n; ++i) {
    mq.push(i - 1);        // 新候选左端点
    mq.popBefore(i - k);   // 保留 j >= i-k
    best = max(best, s[i] - mq.best());
}
```

注意这里窗口是 `[i-k, i-1]`，`popBefore` 的参数与滑动窗口题**不同**（一个是 `i-k+1`，一个是 `i-k`），源于"前缀下标"与"元素下标"的错位。

### 4. 手写环形数组 vs std::deque

`std::deque` 是分块链表，节点分散、缓存不友好；手写环形数组用一段连续内存 + 取模移动头尾指针，常数显著更小。源码中 `MaxQueueRing` 与 `MaxQueueStl` 接口完全一致（`push / popBefore / best`），通过模板 `slidingWindowMax<Q>` 复用，`main` 里对 n=2×10⁶、k=5000 做了同数据基准对比。

环形实现两个关键细节：
- `cap = n + 2`：环形缓冲区满与空的判据都是 `head == tail`，故容量必须**大于**队列可能的最大长度（窗口滑入新元素时队列可短暂达到 k+1 个）；
- 取模回退：`(tail + cap - 1) % cap`，避免负数取模问题。

## 三、复杂度对比

| 实现 | 单次 push | 单次查询 | 空间 | 备注 |
|---|---|---|---|---|
| 暴力扫窗口 | O(k) | O(k) | O(1) | 仅作对拍 |
| std::deque 单调队列 | 均摊 O(1) | O(1) | O(k) | 简洁，常数大 |
| 手写环形数组队列 | 均摊 O(1) | O(1) | O(n) | 连续内存，最快 |
| 单调栈（柱状图） | 均摊 O(1) | — | O(n) | 每元素进出各一次 |

## 四、常见坑

1. **窗口左端错位**：滑动窗口最值用 `popBefore(i-k+1)`，前缀和+队列（子段和）用 `popBefore(i-k)`。前者错一位会把窗口缩小一格；后者错一位会允许长度 k+1 的子段。本期镜像对拍专门覆盖了此边界。
2. **弹出条件 `<=` vs `<`**：维护最大值弹出 `<= a[i]`（保留等值元素中最早的下标，活得最久，最优）；若弹 `<`，等值元素会堆积，正确但队列更长。
3. **柱状图等高柱子**：弹出条件用 `>`（不弹等高）时，最左侧等高柱会在更矮元素到来时获得完整宽度，答案仍正确；用 `>=` 逐个结算也对。两种都能过，但要统一——混用必错。
4. **环形容量不足**：`cap` 必须 ≥ 最大队列长度 + 1。本期取 `n+2` 留足余量，否则首尾指针重合误判为空。
5. **哨兵遗漏**：柱状图不加固末尾哨兵，栈中剩余柱子的矩形永远不会结算。
6. **`std::deque` 的 `pop_front/front`** 与 `vector` 栈的 `back/pop_back` 命名不同，封装成统一接口（`push/popBefore/best`）可让算法层完全复用。
